= Spring Data Aerospike Runnable Examples

This folder contains small framework-owned examples that compile against the current repository sources. They are
intended as copyable reference code for Spring Data Aerospike features, not as full Spring Boot applications.

The root Maven build imports `examples/src/main/java` as test-scoped source so IDEs can treat these examples as regular
Java code. This lets readers navigate repository methods and Spring Data Aerospike APIs without packaging examples into
the published library artifact. The examples are not independently versioned; they compile and run against the
dependencies declared by the current root `pom.xml`.

For application walkthroughes, use the
https://github.com/aerospike-community/spring-data-aerospike-demo[spring-data-aerospike-demo] repository.

== Configuration Style

The examples use Java configuration classes with explicit `@Bean` methods for runnable example objects.
Spring supports both this JavaConfig style and component scanning: `@ComponentScan` discovers classes annotated with
`@Component` and related stereotypes, while an explicit `@Bean` method registers exactly the object returned by that
method.

This folder prefers explicit beans because the runner starts a focused Spring context for one registered scenario at a
time. Keeping the runnable example bean in the selected configuration class makes dependencies visible and avoids
scanning unrelated examples.

Use `@Configuration(proxyBeanMethods = false)` when bean methods do not call other bean methods directly. Declare
collaborators as method parameters so Spring injects repository, template, transaction, or support beans:

[source,java]
----
@Bean
BlockingRepositoryCrudExample blockingRepositoryCrudExample(MovieRepository repository) {
    return new BlockingRepositoryCrudExample(repository);
}
----

Repository interfaces are still discovered through `@EnableAerospikeRepositories` or
`@EnableReactiveAerospikeRepositories`; only the runnable example and local service beans avoid component scanning. A
Spring Data Aerospike user can copy the configuration, entity, repository, and example class as a small working slice,
or adapt the runnable class to `@Component` in their Spring Boot application that already uses component scanning.

`ExampleRegistry` and `ExampleFixture` are runner infrastructure. They keep execution repeatable and safe, but they are
not application code that users need to copy.

== Examples

Run `./examples/run_examples list` to list the currently registered examples.

The query examples use the terminology defined in
link:../src/main/asciidoc/reference/query-methods-preface.adoc#query-terminology[Query Terminology]:
derived query, declared query, custom query, and combined query.

The current set covers:

* `BlockingRepositoryCrudExample` (`blocking-crud` via examples runner) - blocking `AerospikeRepository` save, batch save, read by id, read many ids, read all, count, exists, and delete operations.
* `ReactiveRepositoryCrudExample` (`reactive-crud` via examples runner) - reactive `ReactiveAerospikeRepository` save, batch save, publisher id overloads, read all, count, exists, and delete operations.
* `SecondaryIndexQueryExample` (`indexed-query` via examples runner) - a blocking derived query backed by the secondary index declared in `QueryAerospikeConfiguration`.
* `ProjectionExample` (`projection` via examples runner) - DTO and dynamic target-class projection from repository methods.
* `IndexedAnnotationExample` (`indexed-annotation` via examples runner) - startup index creation from the `@Indexed` annotation.
* `IndexedContextExample` (`indexed-context` via examples runner) - startup index creation from `@Indexed` with a nested Aerospike context.
* `BlockingDeclaredQueryExample` (`blocking-declared-query` via examples runner) - blocking declared repository query using a Spring Data Aerospike `@Query` DSL expression and `indexToUse`.
* `CustomQueryTypesExample` (`blocking-custom-query-types` via examples runner) - blocking custom query examples for regular, id, id-plus-bin, metadata, DSL, filtering, and expression-index qualifiers.
* `BlockingRepositoryQueryMethodsExample` (`blocking-query-methods` via examples runner) - blocking derived queries for read, exists, count, and delete operations backed by secondary indexes.
* `BlockingRepositoryDerivedIdAndBinQueryExample` (`blocking-derived-query-id-bin` via examples runner) - blocking derived queries that combine id criteria with a regular bin criterion.
* `ReactiveRepositoryQueryMethodsExample` (`reactive-query-methods` via examples runner) - reactive derived queries for read, exists, count, and delete operations backed by secondary indexes.
* `ReactiveRepositoryDerivedIdAndBinQueryExample` (`reactive-derived-query-id-bin` via examples runner) - reactive derived queries that combine id criteria with a regular bin criterion.
* `PaginationAndSortingExample` (`pagination-sorting` via examples runner) - repository sorting, `Page`, `Slice`, and sorted offset pagination with secondary indexes.
* `ProgrammaticCustomQueryExample` (`blocking-custom-query-programmatic` via examples runner) - blocking custom queries with programmatic `Qualifier` objects and target-class projection.
* `ProgrammaticCustomQueryIdAndBinExample` (`blocking-custom-query-id-bin` via examples runner) - blocking custom queries that combine id qualifiers with a regular bin qualifier.
* `ReactiveProgrammaticCustomQueryExample` (`reactive-custom-query-programmatic` via examples runner) - reactive custom queries with programmatic `Qualifier` objects and target-class projection.
* `ReactiveProgrammaticCustomQueryIdAndBinExample` (`reactive-custom-query-id-bin` via examples runner) - reactive custom queries that combine id qualifiers with a regular bin qualifier.
* `BlockingDerivedQueryConjunctionExample` (`blocking-derived-query-conjunction` via examples runner) - blocking combined derived query conjunctions that use secondary indexes with scans disabled.
* `ReactiveDerivedQueryConjunctionExample` (`reactive-derived-query-conjunction` via examples runner) - reactive combined derived query conjunctions that use secondary indexes with scans disabled.
* `BlockingDerivedQueryDisjunctionExample` (`blocking-derived-query-disjunction` via examples runner) - blocking combined derived query disjunctions and mixed top-level disjunctions that scan even when a secondary index exists.
* `ReactiveDerivedQueryDisjunctionExample` (`reactive-derived-query-disjunction` via examples runner) - reactive combined derived query disjunctions and mixed top-level disjunctions that scan even when a secondary index exists.
* `BlockingDerivedQueryNoIndexExample` (`blocking-derived-query-no-index` via examples runner) - blocking combined derived queries in a scan-enabled context with no secondary index.
* `ReactiveDerivedQueryNoIndexExample` (`reactive-derived-query-no-index` via examples runner) - reactive combined derived queries in a scan-enabled context with no secondary index.
* `BlockingCustomQueryConjunctionExample` (`blocking-custom-query-conjunction` via examples runner) - blocking combined custom query conjunctions, including `AND(indexedGenre, OR(...))`, backed by secondary index.
* `ReactiveCustomQueryConjunctionExample` (`reactive-custom-query-conjunction` via examples runner) - reactive combined custom query conjunctions, including `AND(indexedGenre, OR(...))`, backed by secondary index.
* `BlockingCustomQueryDisjunctionExample` (`blocking-custom-query-disjunction` via examples runner) - blocking combined custom query disjunctions that scan even when a secondary index exists.
* `ReactiveCustomQueryDisjunctionExample` (`reactive-custom-query-disjunction` via examples runner) - reactive combined custom query disjunctions that scan even when a secondary index exists.
* `BlockingCustomQueryNoIndexExample` (`blocking-custom-query-no-index` via examples runner) - blocking combined custom queries in a scan-enabled context with no secondary index.
* `ReactiveCustomQueryNoIndexExample` (`reactive-custom-query-no-index` via examples runner) - reactive combined custom queries in a scan-enabled context with no secondary index.
* `BlockingDeclaredQueryConjunctionExample` (`blocking-declared-query-conjunction` via examples runner) - blocking combined declared query conjunctions with `@Query` DSL expressions and `indexToUse`.
* `BlockingDeclaredQueryDisjunctionExample` (`blocking-declared-query-disjunction` via examples runner) - blocking combined declared query disjunctions with `@Query` DSL expressions that scan even when a secondary index exists.
* `BlockingDeclaredQueryNoIndexExample` (`blocking-declared-query-no-index` via examples runner) - blocking combined declared queries with `@Query` DSL expressions in a scan-enabled context with no secondary index.
* `BlockingTemplateExample` (`blocking-template` via examples runner) - blocking `AerospikeTemplate` query, count, exists, projection, batch ids, atomic bin mutation, partial update, and custom `WritePolicy` persist operations.
* `ReactiveTemplateExample` (`reactive-template` via examples runner) - reactive `ReactiveAerospikeTemplate` query, count, exists, projection, batch ids, atomic bin mutation, and partial update operations.
* `BlockingCustomConvertersExample` (`blocking-custom-converters` via examples runner) - blocking template operations with custom read/write converters for a composite id.
* `ReactiveCustomConvertersExample` (`reactive-custom-converters` via examples runner) - reactive template operations with custom read/write converters for a composite id.
* `BlockingTransactionExample` (`blocking-transactions` via examples runner) - blocking repository/template writes using `AerospikeTransactionManager` and a proxied `@Transactional` service.
* `ReactiveTransactionExample` (`reactive-transactions` via examples runner) - reactive repository/template writes using `AerospikeReactiveTransactionManager` and `TransactionalOperator`.
* `BlockingCachingExample` (`caching` via examples runner) - Spring Cache annotations backed by `AerospikeCacheManager` using a dedicated example cache set.

Transaction examples report `SKIPPED` on Aerospike Server versions older than 8.0.0.

== Running

List examples without connecting to Aerospike:

[source,bash]
----
./examples/run_examples list
----

Run every live example against a local Aerospike namespace:

[source,bash]
----
./examples/run_examples all --hosts localhost:3000 --namespace test
----

Run one example:

[source,bash]
----
./examples/run_examples blocking-crud --hosts localhost:3000 --namespace test
----

The runner accepts `--fail-fast` to stop at the first failure.

== Namespace Safety

The examples own records and secondary indexes whose names start with `sda_examples_`. They clean up those records and
indexes before or after scenario execution. Query examples that need secondary indexes declare them in the registry
fixture so the runnable code stays focused on application repository/template usage.

By default the runner only performs live cleanup in namespace `test`. To run against another namespace, pass
`--allow-non-test-namespace` explicitly:

[source,bash]
----
./examples/run_examples all --hosts localhost:3000 --namespace dev --allow-non-test-namespace
----

Some combined query examples intentionally enable scans. They demonstrate no-index execution and top-level disjunction
shapes, where Spring Data Aerospike cannot choose a single secondary-index filter even if one predicate is indexed.

== Local Verification

The root Maven build compiles this folder as test-scoped source so IDE import and repository method navigation work out
of the box. Running live examples remains opt-in through `./examples/run_examples`, which selects the `examples` profile
for the `exec:java` runner.

Compile the framework tests and examples without running live examples:

[source,bash]
----
mvn -Pexamples -DskipTests test-compile > examples-test-compile.log 2>&1
----

Run the non-live support tests only:

[source,bash]
----
mvn -Pexamples -Dtest='org.springframework.data.aerospike.examples.support.*Tests' test > examples-support-tests.log 2>&1
----

Run the live smoke set:

[source,bash]
----
./examples/run_examples all --hosts localhost:3000 --namespace test > examples-live-run.log 2>&1
----
