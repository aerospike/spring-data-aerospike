= Spring Data Aerospike Runnable Examples

This folder contains small framework-owned examples that compile against the current repository sources. They are
intended as copyable reference code for Spring Data Aerospike features, not as full Spring Boot applications.

The root Maven build imports `examples/src/main/java` as test-scoped source so IDEs can treat these examples as regular
Java code. This lets readers navigate repository methods and Spring Data Aerospike APIs without packaging examples into
the published library artifact. The examples are not independently versioned; they compile and run against the
dependencies declared by the current root `pom.xml`.

For complete application walkthroughs, use the
https://github.com/aerospike-community/spring-data-aerospike-demo[spring-data-aerospike-demo] repository.

== Examples

Run `./examples/run_examples list` to list the currently registered examples.

The current set covers:

* `blocking-crud` - blocking `AerospikeRepository` save, batch save, read by id, read many ids, read all, count, exists, and delete operations.
* `reactive-crud` - reactive `ReactiveAerospikeRepository` save, batch save, publisher id overloads, read all, count, exists, and delete operations.
* `indexed-query` - a blocking derived query backed by an explicitly created secondary index.
* `projection` - DTO and dynamic target-class projection from repository methods.
* `indexed-annotation` - startup index creation from the `@Indexed` annotation.
* `custom-query-dsl` - a declared repository query backed by a Spring Data Aerospike `@Query` DSL expression.
* `blocking-query-methods` - blocking derived queries for read, exists, count, and delete operations backed by fixture-managed secondary indexes.
* `reactive-query-methods` - reactive derived queries for read, exists, count, and delete operations backed by fixture-managed secondary indexes.
* `blocking-custom-query-programmatic` - blocking custom queries with programmatic `Qualifier` objects and target-class projection.
* `reactive-custom-query-programmatic` - reactive custom queries with programmatic `Qualifier` objects and target-class projection.
* `blocking-derived-query-conjunction` - blocking combined derived query conjunctions that use fixture-created `lGenre`/`lTitle` secondary indexes with scans disabled.
* `reactive-derived-query-conjunction` - reactive combined derived query conjunctions that use fixture-created `lGenre`/`lTitle` secondary indexes with scans disabled.
* `blocking-derived-query-disjunction` - blocking combined derived query disjunctions and mixed top-level disjunctions that scan even when `lGenre` is indexed.
* `reactive-derived-query-disjunction` - reactive combined derived query disjunctions and mixed top-level disjunctions that scan even when `lGenre` is indexed.
* `blocking-derived-query-no-index` - blocking combined derived queries in a scan-enabled context with no secondary index.
* `reactive-derived-query-no-index` - reactive combined derived queries in a scan-enabled context with no secondary index.
* `blocking-custom-query-conjunction` - blocking combined custom query conjunctions, including `AND(indexedGenre, OR(...))`, backed by `lGenre`.
* `reactive-custom-query-conjunction` - reactive combined custom query conjunctions, including `AND(indexedGenre, OR(...))`, backed by `lGenre`.
* `blocking-custom-query-disjunction` - blocking combined custom query disjunctions that scan even when `lGenre` is indexed.
* `reactive-custom-query-disjunction` - reactive combined custom query disjunctions that scan even when `lGenre` is indexed.
* `blocking-custom-query-no-index` - blocking combined custom queries in a scan-enabled context with no secondary index.
* `reactive-custom-query-no-index` - reactive combined custom queries in a scan-enabled context with no secondary index.
* `blocking-declared-query-conjunction` - blocking combined declared query conjunctions with `@Query` DSL expressions and `indexToUse`.
* `blocking-declared-query-disjunction` - blocking combined declared query disjunctions with `@Query` DSL expressions that scan even when `lGenre` is indexed.
* `blocking-declared-query-no-index` - blocking combined declared queries with `@Query` DSL expressions in a scan-enabled context with no secondary index.
* `blocking-template` - blocking `AerospikeTemplate` query, count, exists, projection, batch ids, atomic bin mutation, partial update, and custom `WritePolicy` persist operations.
* `reactive-template` - reactive `ReactiveAerospikeTemplate` query, count, exists, projection, batch ids, atomic bin mutation, and partial update operations.
* `blocking-custom-converters` - blocking template operations with custom read/write converters for a composite id.
* `reactive-custom-converters` - reactive template operations with custom read/write converters for a composite id.
* `blocking-transactions` - blocking repository/template writes using `AerospikeTransactionManager` and a proxied `@Transactional` service.
* `reactive-transactions` - reactive repository/template writes using `AerospikeReactiveTransactionManager` and `TransactionalOperator`.

Transaction examples report `SKIPPED` on Aerospike Server versions older than 8.0.0.

== Running

List examples without connecting to Aerospike:

[source,bash]
----
./examples/run_examples list
----

Run every live example against a local Aerospike namespace:

[source,bash]
----
./examples/run_examples all --hosts localhost:3000 --namespace test
----

Run one example:

[source,bash]
----
./examples/run_examples blocking-crud --hosts localhost:3000 --namespace test
----

The runner accepts `--fail-fast` to stop at the first failure.

== Namespace Safety

The examples own records and secondary indexes whose names start with `sda_examples_`. They clean up those records and
indexes before or after scenario execution. Query examples that need secondary indexes declare them in the registry
fixture so the runnable code stays focused on application repository/template usage.

By default the runner only performs live cleanup in namespace `test`. To run against another namespace, pass
`--allow-non-test-namespace` explicitly:

[source,bash]
----
./examples/run_examples all --hosts localhost:3000 --namespace dev --allow-non-test-namespace
----

Some combined query examples intentionally enable scans. They demonstrate no-index execution and top-level disjunction
shapes, where Spring Data Aerospike cannot choose a single secondary-index filter even if one predicate is indexed.

== Local Verification

The root Maven build compiles this folder as test-scoped source so IDE import and repository method navigation work out
of the box. Running live examples remains opt-in through `./examples/run_examples`, which selects the `examples` profile
for the `exec:java` runner.

Compile the framework tests and examples without running live examples:

[source,bash]
----
mvn -Pexamples -DskipTests test-compile > examples-test-compile.log 2>&1
----

Run the non-live support tests only:

[source,bash]
----
mvn -Pexamples -Dtest='org.springframework.data.aerospike.examples.support.*Tests' test > examples-support-tests.log 2>&1
----

Run the live smoke set:

[source,bash]
----
./examples/run_examples all --hosts localhost:3000 --namespace test > examples-live-run.log 2>&1
----

CI/CD wiring, report publishing, generated snippets, and automatic documentation rendering are intentionally left for a
later iteration.
